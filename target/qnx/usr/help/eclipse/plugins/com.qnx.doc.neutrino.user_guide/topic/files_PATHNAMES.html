Filenames and pathnames

To access any file or directory, you must specify a pathname, a symbolic name that tells a program where to find a file within the directory hierarchy based at root (/).

A typical QNX OS pathname looks like this:

/home/fred/.profile

In this example, .profile is found in the fred directory, which in turn resides in the home directory, which is found in /, the root directory:

Like Linux and other Unix-like operating systems, QNX OS pathname components are separated by a forward slash (/). This is unlike Microsoft operating systems, which use a backslash (\).

Note: To explore the files and directories on your system, use the ls utility. This is the equivalent of dir in MS-DOS. For more information, see Basic commands in Using the Command Line, or ls in the Utilities Reference.
  • Absolute and relative pathnames
  • Dot and dot-dot directories
    Most directories contain two special links, . (dot) and .. (dot dot).
  • No drive letters
    Unlike Microsoft Windows, which represents drives as letters that precede pathnames (e.g., C:\), QNX OS represents disk drives as regular directories within the pathname space. Directories that access another filesystem, such as one on a second hard disk partition, are called mountpoints.
  • Pathnames that begin with a dot
    When you list the contents of a directory, the ls utility usually hides files and directories whose names begin with a period. Programs precede configuration files and directories with a period to hide them from view. The files (not surprisingly) are called hidden files.
  • Extensions
    Filename extensions (.something at the end of a filename) tell programs and users what type of data a file contains.
  • Pathname-space mapping
    You may have noticed that we've talked about files and directories appearing in their parent directories, rather than just saying that the parent directories contain these files. This is because in QNX OS, the pathname space is virtual, dictated not just by the filesystem that resides on media mounted at root, but rather by the paths and pathname aliases registered by the process manager.
  • Filename rules
    QNX OS supports a variety of filesystems, each of which has different capabilities and rules for valid filenames.
