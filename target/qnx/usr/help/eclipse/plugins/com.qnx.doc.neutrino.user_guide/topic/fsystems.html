Working with Filesystems

The QNX OS provides a variety of filesystems, so that you can easily access DOS, Linux, as well as native Power-Safe disks.

The Filesystems chapter of the System Architecture guide describes their classes and features.

Under QNX OS:

  • You can dynamically start and stop filesystems.
  • Multiple filesystems may run concurrently.
  • Applications are presented with a single unified pathname space and interface, regardless of the configuration and number of underlying filesystems.

A desktop QNX OS system starts the appropriate block filesystems on booting; you start other filesystems as standalone managers. The default block filesystem is the Power-Safe filesystem.

  • Setting up, starting, and stopping a block filesystem
    When you launch a block device driver (devb-*), it detects the partitions on the block I/O devices. You can then issue mount commands to start the appropriate filesystems for various partitions.
  • Mounting and unmounting filesystems
  • Managing disk quotas
    For the Power-Safe (QNX6) filesystem, you can define disk quotas to limit how many file entries a user or group of users can create and how large these files can grow.
  • Power-Safe filesystem
    The Power-Safe filesystem, supported by the fs-qnx6.so shared object, is a reliable disk filesystem that can withstand power failures without losing or corrupting data.
  • QNX compressed filesystem
    The QNX compressed filesystem (QCFS) provides a read-only filesystem that supports the compression of files and metadata so that they take up less space.
  • Image filesystem
    By an image, we refer to an OS image here, which is a file that contains the OS, your executables, and any data files that might be related to your programs, for use in an embedded system.
  • DOS filesystem
    The DOS filesystem provides transparent access to DOS disks, so you can treat DOS filesystems as though they were QNX OS (POSIX) filesystems. This transparency lets processes operate on DOS files without any special knowledge or work on their part.
  • Linux Ext2 filesystem
    The Linux Ext2 filesystem provided in QNX OS provides transparent access to Linux disk partitions.
  • UDF filesystem
    The Universal Disk Format (UDF) filesystem provides access to recordable media, such as CD, CD-R, CD-RW, and DVD. It's used for DVD video, but can also be used for backups to CD, and so on.
  • FFS3 filesystem
    The Flash FileSystem version 3 (FFS3) drivers implement a POSIX-compatible filesystem on NOR flash memory devices. This filesystem is unique to QNX OS.
  • NFS filesystem
    The Network File System (NFS) protocol is a TCP/IP application that supports networked filesystems. It provides transparent access to shared filesystems across networks.
  • Linux Squash filesystem
    The Linux Squash filesystem (squashfs) is a compressed read-only filesystem that allows you to compress data, inodes, and directories.
  • RAM “filesystem”
    QNX OS provides a simple RAM-based filesystem that allows read/write files to be placed under /dev/shmem.
